# crm-bot-demo — Telegram-бот заявок + amoCRM + админка для заказчика

Бот принимает заявку от клиента (услуга → имя → телефон → описание), создаёт сделку и контакт в **amoCRM** и уведомляет менеджера. **Заказчик сам правит тексты и список услуг в веб-админке, без программиста:** изменения применяются сразу, перезапуск бота не нужен.

Стек: Python · FastAPI · Telegram Bot API · amoCRM REST API v4 · Docker Compose · pytest.

> Учебное демо с условными данными. Без ключей работает в демо-режиме: заявки пишутся в журнал и видны в админке, а в CRM не отправляются.

## Как это устроено

```
клиент в Telegram ──► бот (app/telegram.py, long polling)
                         │
                         ▼
                  диалог (app/dialog.py): шаги, проверка телефона
                         │            ▲
                         │            └── тексты и услуги из content.json (app/content.py)
                         ▼                          ▲
              CRM (app/crm.py): amoCRM или демо     │  правит заказчик
              + журнал leads.jsonl                  │
                         │                  админка (app/admin.py, пароль)
                         ▼
               уведомление менеджеру в Telegram
```

- **Диалог не зависит от Telegram** (`Dialog.handle(chat_id, text) → Reply`), поэтому тестируется без сети.
- **Админка** защищена паролем (HTTP Basic), HTML экранируется, поля проверяются (непустые, до 500 символов, 1–8 услуг), файл настроек пишется целиком или никак; битый файл не ломает бота (берутся значения по умолчанию).
- **amoCRM**: `POST /api/v4/leads/complex` (сделка + контакт с телефоном) и примечание к сделке.

## Запуск

```bash
cp .env.example .env          # впишите ADMIN_TOKEN (пароль админки)
docker compose up --build     # админка: http://localhost:8001 (логин любой, пароль = ADMIN_TOKEN)
```

Чтобы запустить бота: создайте бота у [@BotFather](https://t.me/BotFather), впишите `BOT_TOKEN` (и `MANAGER_CHAT_ID` для уведомлений) в `.env`, затем:

```bash
docker compose --profile bot up --build
```

Для реальной CRM заполните `AMO_SUBDOMAIN` и `AMO_TOKEN` (долгосрочный токен интеграции amoCRM). Пусто: демо-режим.

## Без Docker

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
ADMIN_TOKEN=demo uvicorn app.admin:app --port 8001
BOT_TOKEN=... python -m app.run_bot
```

## Что проверено

16 тестов `pytest`: весь диалог до создания заявки, отклонение неверного телефона, отмена, разные пользователи не смешиваются, **изменение текстов применяется без перезапуска**, админка (пароль, сохранение, отказ на пустые поля, экранирование HTML, битый файл настроек), формирование запросов к amoCRM и обработка ошибки 401 (без сети, через подменённый HTTP-клиент), отправка сообщений и уведомление менеджеру в Telegram (без сети). Админка проверена вручную в Docker (пароль, сохранение, отображение).

## Ограничения (честно)

- Реальный amoCRM и реальный Telegram не проверялись: нужны ключи; запросы к ним проверены тестами на подменённом клиенте.
- Состояние диалога хранится в памяти процесса (после перезапуска бота диалог начинается заново).
- Нет ролей в админке: один пароль на всех.
